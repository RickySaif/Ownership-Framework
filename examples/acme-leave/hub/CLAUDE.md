# Acme QA Hub: rules for Claude

This repo is a **QA hub**. It tests the apps below from the outside and keeps the evidence. It does not contain or
change their code. Generated by the Ownership Framework `ownership-setup` skill on 2026-10-23; edit freely.

## Apps

| App | Bug prefix | Owner | Repo | Branch | Environments |
|---|---|---|---|---|---|
| acme-leave | AL | Dana Owner (fictional) (dana@acme.example) | ../app | main | local, staging |

Owners decide what is "by design". Ask them before recording a bug whose requirement is unclear.

## Always

1. Expected behaviour comes from the requirements (acme-leave: apps/local/acme-leave/docs/prd.md), not from what the app shows now. Work out
   money and date values by hand first.
2. Confirm a suspected bug two ways: the response (UI or API) **and** the stored state (API read-back or read-only DB
   query). Then rule out "by design" with the owner above.
3. Helpers throw on failure. No assertion that cannot fail, no `|| true`.
4. Only change what you created: name it `<run-id>-…`, record it with `track()` in the run ledger, clean up from the
   ledger only. Never edit or delete data that existed before the run.
5. `apps/` is read-only: never edit, commit or run setup inside it. Query the code graph first
   (`graphify query "…" --graph graphify-out/<env>/<app>/graph.json`), then read only the files it points to.
6. Before testing, `npm run sync:check`. If it fails, stop and say why.
7. Hub changes to specs, `knownBug` markers or bug states go through a pull request, never straight to main.
8. Red stops the line: a new regression is reported before any new exploratory work. A failing spec is a regression
   unless a merged change or a requirement says the behaviour was meant to change.
9. Secrets live in the OS keychain or env, never in files, commits, bug reports, videos or screenshots.

## Environments and database access

| App | Env | URL | Database | DB access | Reached by | Restores nightly |
|---|---|---|---|---|---|---|
| acme-leave | local | http://localhost:4310 | sqlite `.local-db/acme-leave.db` | read-write (throw-away) | direct | n/a |
| acme-leave | staging | https://staging.acme.example | postgres db.staging.acme.example:5432/acme_leave | read-write | SSH tunnel via qa@bastion.acme.example | yes |

Rules (see `playbook/safety.md`):
- **Local**: full read and write, free to reset. Writes only when `QA_ISOLATED_DB` names the local database.
- **Dev / staging**: reads are fine. Writes only through `db.write()`: rows this run created or the permanent test
  accounts, one transaction, row cap, before/after logged to the ledger, SQL saved under `qa/<app>/db-actions/`.
  Prefer the app's UI or API so its business rules run; use the DB to confirm state, set up data the UI cannot
  create, and move dates for time-based features.
- **Production**: read-only smoke on synthetic accounts only. The AI never writes to production. DB reads only with a read-only role.

### Production exceptions

None. Any exception must be added here and in `registry.yaml` with who approved it, the scope and an end date.

## What this hub does

- Test types: spec assurance, exploratory hunts, smoke checks, regression runs
- Deliverables for each confirmed bug: bug file, captioned video, regression spec with knownBug, smoke suite, board with fix prompts, requirements coverage table
- Routines: acme-leave nightly at 01:30 on staging, hard stop 06:00; acme-leave weekly at Sat 09:00 on staging, hard stop 13:00 (time zone Asia/Jakarta)
- Board: published to GitHub Pages from board/dist (board skill)

## Where things go

| What | Where |
|---|---|
| Bug | `qa/<app>/bugs/<ID>.json` (schema in `schemas/bug.schema.json`, check with `npm run validate`) |
| Video | `qa/<app>/videos/<ID>-<slug>.webm` (demos in `qa/<app>/videos/demos/`, record with `npm run videos`) |
| Regression spec | `qa/<app>/specs/regression/*.spec.mjs` (check with `npm run strict-check`) |
| Smoke spec | `qa/<app>/specs/smoke/*.spec.mjs` (read-only) |
| Exploratory notes | `qa/<app>/explore/` |
| SQL the run used | `qa/<app>/db-actions/` |
| Run records | `runs/<app>/<run-id>/` (status.json, ledger.jsonl, charters/, findings.json, report.md) |
